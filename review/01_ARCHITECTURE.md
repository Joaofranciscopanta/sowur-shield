## 6. Combat System (`Scripts/Combat/`, 24 files)

### Pipeline (SampleScene → CombatScene → Results)

| Stage | File:Line | Mechanism |
|-------|-----------|-----------|
| Enter trigger zone | `CombatTriggerZone.cs:107` | `Interact()` → `TeamAssemblerUI.Instance.OpenAssembler()` |
| Team assembler opens | `TeamAssemblerUI.cs:103` | Builds grid UI from owned animals |
| Stage selection | `StageButton.cs:49-53` | `StageManager.SetSelectedStage()` persists choice |
| Scene load | TeamAssemblerUI button → `SceneManager.LoadScene("CombatScene")` | Team data persisted via `TeamAssemblerData.Instance` (DontDestroyOnLoad MonoBehaviour) |
| Grid generation | `GridManager.cs:67-71, 76-126` | 9×5 grid, cell size 1.0, generated in `Start()` |
| Player spawn | `CombatTeamSpawner.cs:48-54` | `Invoke(SpawnTeams, 0.5f)` |
| Enemy spawn | `EnemySpawner.cs:35-39` | `Invoke(SpawnEnemies, 0.6f)` |
| Combat init | `TurnManager.cs:80-84` | `Invoke(InitializeCombat, 1.0f)` |
| Turn loop | `TurnManager.cs:133-148` | `Update()` drives gauge fill → ready-unit processing → battle-end check |
| Results | `TurnManager.cs:459-495` → `BattleResultsUI.cs:247-285` | `EndBattle()` computes rewards, shows UI; `AwardRewards()` on "Return to Farm" |

### Grid Layout (GridManager.cs:73-126)
- **9 columns (0-8) × 5 rows (0-4)**.
- **Enemy side**: columns 0-5 (30 cells). **Player side**: columns 6-8 (15 cells).
- This **confirms CLAUDE.md/ROADMAP's "cols 0-5 enemy, 6-8 player"** and **contradicts the PRD's
  row-based description** ("Player side: Rows 1-3, Enemy side: Rows 4-5"). The PRD's grid
  description is stale/aspirational — ground truth is column-based, enemy-left/player-right.
- Cell size 1.0, world positions centered at origin via `gridOffset` computed from
  `gridWorldWidth`/`gridWorldHeight` (GridManager.cs:89-105).

### Turn Gauge / ATB (TurnManager.cs)
- **No coroutine for main loop** — driven entirely by `Update()` (TurnManager.cs:133-148).
- `FillTurnGauges()` (164-173): `gauge += speed * deltaTime * gaugeFilLRate` (default `gaugeFilLRate=10f`).
- Gauge capped at 100 (`CombatUnit.cs:384-387`); on action, `gauge -= 100` preserving overflow
  (CombatUnit.cs:405) — so a speed-20 unit at fill-rate 10 can act ~2x/sec with correct overflow carry.
- `ProcessReadyUnits()` (179-204) sorts ready units by speed desc, batches via
  `ProcessActionBatch()` coroutine (209-230) with `actionMicroDelay=0.05f` between actions.

### Skill vs Basic Attack (TurnManager.cs:236-284, CombatUnit.cs:597-625)
- Player: `playerActiveSkill != null && type==Active && cooldownRemaining<=0` → use skill.
- Enemy: has `enemySkills` AND `Random.value <= skillUseChance` (default 0.3) → random skill.
- Otherwise: `SelectTarget()` + `ExecuteAttack()` (basic attack).

### Status Effects (CombatStatusEffect.cs, CombatUnit.cs:621-706, TurnManager.cs:244-339)
- **Shield**: self-buff, damage reduction fraction, summed and capped at 0.9 (90%) in
  `GetShieldReduction()` (CombatUnit.cs:692-706).
- **Stun**: skip-turn, checked via `IsStunned` (CombatUnit.cs:681-690) after ticking.
- **Burn**: DoT, accumulated in `TickStatusEffects()` (CombatUnit.cs:662-679), applied via
  `TakeDamageWithShield()`.
- **Immunities**: `EnemyData.immunities` (string list, case-insensitive) → `IsImmuneTo()`
  (CombatUnit.cs:632-641). Checked before Stun/Burn application (TurnManager.cs:331,336).

### Stat Pipeline: Animal → CombatUnit
- Player units: `CombatTeamSpawner.cs:149-165, 233-256` reads `Animal.GetCombatStats()` →
  `AnimalCombatStats` (MaxHealth, CurrentAttack/Defense/Speed/Accuracy).
- Growth multipliers (petting/feeding bonuses), seasonal modifiers, and illness penalty are all
  **pre-applied at the Animal layer** before CombatUnit ever sees the numbers
  (`ApplyStatMultiplier()` at CombatUnit.cs:560-567 for illness).
- **CombatUnit has zero visibility into "why" a stat is what it is** — no synergy/family/class
  bonus calculation exists in the combat system itself (see Section 9 — PRD gap).
- Enemy units: `EnemySpawner.cs:189-231` calls `EnemyData.GetScaledStats(difficulty)`
  (EnemyData.cs:108-137) — base stats × `pow(scaling, difficulty-1)` × type bonus. Accuracy
  hardcoded to 1.0 for enemies (CombatUnit.cs:165).

### Visuals (CombatUnit.cs:178-309)
`SetupVisuals()` priority order:
1. `animal.AnimalData.idleSprite` if present (line 181) → `CreateSpriteVisual()`.
2. Existing `SpriteRenderer` on the GameObject with a sprite (lines 188-191) → `CreateSpriteVisual()`.
3. Fallback: colored sphere primitive (`CreateSphereVisual()`, blue=player/red=enemy, material
   `Unlit/Color`).

`CreateSpriteVisual()` (202-241): ensures material `Sprites/Default`, sort order 10,
`NormalizeSpriteSize()` scales sprite to ~0.8 world units (fits 1×1 grid cell), player sprites
flipped to face right.

### Rewards
- `ComputeRewards()` (TurnManager.cs:507-544): gold via `stage.CalculateGoldReward()`, xp via
  `stage.baseExperienceReward`, loot via `stage.RollLoot()`. Marks
  `worldFlags["stage_completed_{stageName}"] = true` and calls `StageManager.CompleteStage()`.
- `AwardRewards()` (BattleResultsUI.cs:247-272): applied on "Return to Farm" click — adds gold to
  `PlayerStats`, loot to `Inventory`, happiness/XP to surviving animals via
  `GainCombatExperience()`, then `SaveManager.Instance.SaveGame()`.

## 7. Farming, Economy, Save, Time Systems

### Farming State Machine (SoilBlockInteractable.cs)
- 4 states: Regular → Tilled → Watered → WithCrop. Event-driven transitions, confirmed clean by
  exploration agent — no issues found in state logic itself.
- Crop growth (CropGrowthManager.cs): multi-stage progression configured per-crop via CropData
  ScriptableObject (days per stage, water requirements, seasonal restrictions, regrowth).
- Greenhouse seasonal-restriction bypass implemented at `SoilBlockInteractable.cs:400-414`.

### Inventory & Economy
- **Inventory.cs**: previously 1146 lines (Feb audit) — now reported as **1150 lines**, but
  **slot-level visual/drag logic has been split out** into `SlotVisualController` and
  `SlotDragHandler` (new files in `Scripts/Inventory/`). `InventorySlot.cs` is now **907 lines**
  (down from 902 in Feb — roughly flat, the split moved responsibility without shrinking the
  remaining file much).
- **SellBox.cs**: **1123 lines** (up from 1109 in Feb). `sellMultiplier` is a computed property
  reading from `GameBalance` (default 0.8). `GameBalance` is read in a property getter
  (SellBox.cs:67) on every access rather than cached — minor inefficiency, not correctness issue.
- **ItemStack.cs**: 130 lines, clean, delegates to `InventoryContainer`.
- Shop system (ShopData/ShopNPC/ShopUI) wired to `PlayerStats.money` — confirmed functional by
  exploration (not flagged as broken).

### Save/Load System
- `GameData.cs` / `SaveManager.cs`: multi-slot (AutoSave + Slot1-3), `ISaveable` registry pattern
  confirmed working.
- **Save versioning is a stub**: `SaveManager.cs:393-397` — `MigrateSave()` exists as a method but
  contains **no actual field-transformation logic**. If `GameData` schema changes (new fields
  added to nested objects), old saves will deserialize with default values for new fields (JSON
  deserialization tolerates missing fields in most .NET JSON libs) but there's **no mechanism to
  run data-migration logic** (e.g., recomputing a derived field, renaming a key). This is a latent
  risk for any future schema change, not an active bug today.

### Time / Weather / Buildings
- `TimeController.cs`: `OnDayChanged`/`OnSeasonChanged` events confirmed firing correctly,
  7 days/season (28-day year per ROADMAP, consistent).
- `WeatherController.cs`: Rain (auto-waters tilled/watered soil) and Drought (accelerates
  wilting), once per day, subscribed to `OnDayChanged`. Uses `FindObjectsByType` — acceptable
  overhead at once-per-day frequency.
- `FarmBuildingManager.cs`: Barn/Greenhouse effects via `worldFlags`-prefix persistence pattern,
  confirmed working. No building upgrade levels (single on/off state per building).

### GameBalance ScriptableObject
- Confirmed present at `Assets/Scripts/GameBalance.cs`, ~80% of magic numbers centralized
  (sell multiplier, interaction ranges, happiness formula bounds).
- Crop growth timings remain **per-CropData by design** (not in GameBalance) — this is correct,
  since each crop has different growth curves; not a gap.
- Time-of-day constants (e.g., wake time 0.25f) remain hardcoded in TimeController — flagged as
  low-priority polish, not urgent.

## 8. UI, Dialogue, Animals, Quests

### UI Window System
- `UIManager.cs` has **two coexisting systems**: legacy `allUIPanels`/`currentlyOpenPanel`/
  `OpenPanel`/`ClosePanel` (lines 13-120) AND the documented `openWindowStack`/`TryOpenWindow`/
  `TryCloseWindow` (lines 24-311). 10 classes implement `IUIWindow` and use the new system; the
  legacy system's actual usage needs Phase 2 verification (is anything still calling
  `OpenPanel`/`ClosePanel`?).

### Dialogue System
- `DialogueCondition.ConditionType` **includes `RelationshipLevel`** (confirmed implemented, not
  just planned) — `ConversationMemory.GetRelationshipLevel()` returns float -100..100.
- `DialogueEffect.EffectType` includes `ModifyRelationship`, `GiveItem`/`TakeItem` (wired to real
  `Inventory` via `ItemDatabase`), `SetQuestStatus`.
- `ConversationMemory` (Singleton + ISaveable, 444 lines): auto-saves every 30s if dirty; bridges
  to `GameData.worldData` via prefixed keys (`rel_{npcId}`, `conv_done_{convId}`, `quest_{questId}`,
  `dlgvar_{key}`).
- `NPCDialogueInteractable.cs` (479 lines): **no gift-giving mechanics** — relationship changes
  happen only via dialogue effects (`ModifyRelationship`), not via item-giving interactions. This
  matches "Gift Giving" being listed as unclear/unimplemented in GAME_DEVELOPMENT_PLAN Phase 2.

### Quest System
- `QuestData.cs`: objectives (CollectItem/TalkToNPC/HarvestCrop/CompleteBattle/Custom), rewards
  (gold, items, **relationship rewards** — `QuestRelationshipReward` at line 57).
- `QuestManager.cs` (369 lines, Singleton+ISaveable): `NotifyObjective()` auto-advances matching
  objectives across active quests — called from `ConversationMemory` (dialogue) and presumably
  farming/combat hooks.
- `QuestTrackerUI.cs` (124 lines): corner HUD, single most-recent active quest displayed.

### Animal Husbandry
- `Animal.cs`: **975 lines** — largest single script in the Animals folder, and 2nd largest
  script overall after MainMenuUI.cs.
- Happiness multiplier formula confirmed (Animal.cs:675-680):
  `multiplier = min + (happiness/ceil) * (max-min)`, defaults 0.5x at 0 happiness → 1.5x at 100.
- Daily decay: -0.5 (no pet) / -1.0 (no feed), floor 20 (Animal.cs:695-710).
- Illness system confirmed implemented: 3-day neglect threshold → ill; ill animals can't produce;
  cured by "Medicine" item; -50% stat penalty while ill (`illnessStatPenalty`).
- XP/leveling confirmed: level × 100 XP per level, max level 10, +5% growth-stat boost per level
  (capped 3x total).
- `AnimalData.cs` has fields for `combatClass` (Tank/DPS/Support/Utility), `canStack`/
  `maxStackSize` (synergy-adjacent), and `availablePassiveSkills[]` — **these fields exist but
  whether any system reads `combatClass` or `availablePassiveSkills` to compute combo bonuses is
  UNVERIFIED** (see Section 9).

## 12. Critical Boot → Playable Loop

1. MainMenu scene → `MainMenuManager`/`MainMenuUI` → New Game or Continue → `SceneTransitionManager`
   loads SampleScene (farm).
2. SampleScene: `SaveManager`, `TimeController`, `AnimalRoster`, `QuestManager`,
   `FarmBuildingManager`, `TutorialManager`, `SFXManager`, `GameMusicManager`,
   `WeatherController` initialize (singletons, some DontDestroyOnLoad).
3. Player moves (PlayerMove + new Input System), interacts via `InteractionManager`
   (E-key proximity) or `CursorController` (left-click), farms (SoilBlockInteractable →
   CropGrowthManager), manages animals (Animal, AnimalZone, FeedingTrough), sells via SellBox,
   talks to NPCs (NPCDialogueInteractable → DialogueTreeUI → ConversationMemory), tracks quests
   (QuestManager → QuestTrackerUI), shops (ShopNPC → ShopUI).
4. Sleep → `OnDayChanged` fires → crops grow, animals decay/produce, weather rolls, auto-sell,
   auto-feed via FeedingTrough, tutorial steps advance, AutoSave triggers.
5. Combat entry: `CombatTriggerZone` (E-key) → `TeamAssemblerUI` → pick team → "Start Battle"
   (sets `Time.timeScale=1`) → load CombatScene.
